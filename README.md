# 轻答 · QQ 小号 AI 自动回复

原生 Android 应用，Kotlin + Jetpack Compose + **Miuix 0.5.1**。绑定 QQ 小号所在的应用实例，通过系统通知检测 `@小号`，结合该群近期上下文、注入系统提示词后调用 AI，再由小号通过原群通知的快捷回复入口直接发送，不需要复制粘贴。

源码：https://github.com/DeepShawn/Bot

## 小米应用双开使用步骤

1. 安装轻答（Android 8.0 及以上）。在小米「设置 → 应用设置 → 应用双开」开启 QQ 双开，登录小号，让大号、小号加入同一个群。
2. 在 QQ 和双开 QQ 中开启通知、消息详情及目标群的通知，将小号 QQ 留在后台。
3. 在轻答总览点击「通知使用权」，允许「轻答 · QQ 通知监听」，回来确认监听已连接。允许轻答自启动、后台运行，电池策略设为不限制。
4. 打开「触发规则 → 绑定 QQ 小号 → 检测小号的新通知」。检测窗口为 60 秒，会暂停自动回复。用大号给小号发送一条新消息。通知出现后，轻答会显示 Android 用户、UID、正文和快捷回复能力。
5. 选择刚收到小号通知的实例，点击「将这个实例绑定为小号」。建议分别给大号、小号发消息，对比实例标识，避免绑定错误。这里绑定的是 **Android 应用实例，并非 QQ 账号登录授权**；同一实例内换 QQ 账号后必须重新核对。
6. 填写 **小号的昵称 / 群名片**，每行一个，不带 `@`。可限制允许回复的群名称，与 QQ 通知标题精确匹配，选择是否启用群聊上下文及最近 5 / 10 / 20 条消息，保存规则。
7. 在「AI 配置」选提供商模板，填写该平台自己的 API Key，检查模型，选择或编辑系统提示词，保存并测试连接。
8. 在总览开启自动回复。之后大号发送 `@小号 今天有什么安排？`，匹配后自动请求 AI 并通过原通知回复，无需每条消息手动确认。

部分 Android 13+ 手机首次授权时需先在「应用信息 → 右上角 → 允许受限制的设置」中允许。

**小米兼容性需要实际检测：** 不同 MIUI/HyperOS 版本可能不向普通通知监听服务开放双开空间的通知。若大号通知可见、小号始终不出现，应用不能跨越系统用户隔离读取它。若系统把两个账号呈现为相同实例，也无法保证区分。QQ 若没有正文或 RemoteInput「回复」按钮，会显示原因并禁止绑定为自动回复来源。“支持实例绑定”不代表所有小米系统已通过真机验证。

## 提供商自动填充

| 提供商 | 基础地址 | 默认模型 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com` | `deepseek-flash` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| 通义千问 / 百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| Moonshot / Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `deepseek-ai/DeepSeek-V3.2` |
| 火山方舟 / 豆包 | `https://ark.cn-beijing.volces.com/api/v3` | 填写实际模型或 `ep-` 接入点 ID |
| 自定义 | 保留当前地址 | 保留当前模型 |

模板自动填地址和模型，不含真实密钥。切换服务商时清空密钥，防止发往另一平台；同一服务商但当前地址不同也会清空。所有模板可继续编辑，国际站、其他地域和专属接入点请按控制台修改。

DeepSeek 默认名称按 2026-10-30 的[官方文档](https://api-docs.deepseek.com/)使用 `deepseek-flash`，另可选 `deepseek-v4-pro`；对官方地址发送 `thinking: {"type":"disabled"}`，便于快速回复。其他平台预置名称不保证在所有账号下可用，以各平台控制台为准。

「用当前密钥获取模型」向当前基础地址下的 `/models` 请求并解析 `data[].id`，可搜索并点选。部分平台不提供此接口，失败时手动填写模型即可，不自动切换服务商。

仅支持 HTTPS 的 OpenAI Chat Completions 兼容接口，可填基础地址或完整 `/chat/completions` 地址。应用只追加 `/chat/completions`，不会猜测缺失的 `/v1`。不支持仅 Responses API、Anthropic Messages API、不同认证头或只支持流式的模型。所选模型需支持 `max_tokens` 参数。

## 系统提示词注入

「AI 配置 → 回复风格」提供 **群聊助手、简洁回复、代码助手** 模板，选中后可继续编辑并保存。

每次自动回复和连接测试均发送独立的角色消息：

```json
{
  "messages": [
    {"role": "system", "content": "你保存的系统提示词"},
    {"role": "user", "content": "清理 @小号 后的当前问题"}
  ]
}
```

提示词不会拼进用户问题；留空使用默认群聊助手。开启上下文时，在 system 与当前 user 问题之间附加同群近期 user / assistant 消息；群成员消息不会成为 system 指令。实际输出受模型和服务商行为影响。

## 群聊上下文

默认开启，可在「触发规则」选择最近 5、10 或 20 条，也可关闭或清空缓存。只积累启用自动回复后，绑定小号在允许范围内收到的通知内容，以及轻答已提交的回复；不会读取 QQ 数据库或完整群聊历史。

按实例和会话隔离，最多缓存 20 个会话，每个最多 30 条；API 实际附带最近 30 分钟内、最多 5000 字符的背景。上下文只留在内存，配置变更、监听断开、服务结束、应用进程重启时清空。QQ 不提供稳定会话 ID 时，使用通知 key 加标题区分；标题变化可能造成上下文断开，相同标题的模糊通知无法作为完整群 ID 使用。

开启此功能后，同群近期可见消息也会发送到你选择的 AI 服务；关闭上下文后只发送当前触发问题。

## 回复规则和边界

- 仅接收官方 QQ 包名 `com.tencent.mobileqq`。小米系统双开通常仍用此包名，通过 Android 用户和 UID 区分实例；Android 10 以下以包名和用户区分。不支持 TIM、第三方改包 QQ、其他手机或电脑 QQ。
- 必须先绑定，再开启回复。未绑定、大号所属的其他实例、非允许列表会话均不请求 AI。旧版升级后没有绑定信息会暂停，须先绑定。
- 会话去重和冷却包含实例来源，防止双开用户的相同 shortcut ID 混淆。发送前再次检查通知及来源，用原通知的 PendingIntent 回复，不猜测 QQ 跳转链接或收件人。
- 按通知文本严格匹配昵称。昵称后需为空格、标点或文本结束，避免把 `@小明同学` 识别成 `@小明`。无法取得 QQ 协议中的真实 @ 成员 ID，重名和通知格式变化会影响匹配。
- 默认关闭「[有人@我]」兼容。QQ 可能保留旧标记；开启后只匹配当前正文开头，不扫描历史、摘要或大文本。
- 分组摘要不触发，MessagingStyle 只查最新一条。同群通知更新可继续完成原 @ 的回复；通知被移除、切换到不同会话、权限断开、配置变化或手动关闭时取消未提交的回复，不补回历史通知。
- 相同指纹去重 24 小时，最多 1000 条哈希。旧格式没有稳定消息 ID 时，同一实例的完全相同内容在此期间仅处理一次，也可能跳过真实重复提问。
- 同一会话冷却 10～300 秒（默认 20）；每小时全局滚动请求上限 1～120 次（默认 30）。请求前保存去重和限流，失败也计入。最多并行 3 条，不积压、不重试。
- 用户输入截断为 6000 字符，请求 `max_tokens=400`，回复不超过 500 字符；输出 `@` 转为 `﹫`，减少互相触发。
- 「已提交」仅表示 Android 已交给 QQ，无法确认服务器实际送达，请以 QQ 内消息为准。

聊天在前台、群静音、隐藏通知详情、锁屏隐藏正文或后台被杀时可能无法触发。无需 root，不使用无障碍点击，不修改 QQ，不读 QQ 私有数据库。

## 数据和密钥

API Key 用 Android Keystore 的 AES-GCM 加密保存在设备私有存储，禁用云备份与数据迁移。普通配置、绑定来源、统计及最近 80 条状态仅存本机。检测候选实例和群聊上下文仅在内存中。去重持久化 SHA-256 指纹与时间，不将正文写入本机持久存储；日志不记录正文、发送人、会话名、完整服务端错误或密钥。

开启后匹配消息、系统提示词和启用的同群上下文会发往配置的 API 服务；连接测试也调用模型，按服务商规则计费。获取模型仅请求当前服务商。应用禁止明文地址、URL 用户信息、查询参数及重定向，不含分析或云端日志。

## 构建和验证

使用 JDK 17 或 21、Android SDK 35、Gradle Wrapper 8.13。用 Android Studio 打开项目，设置 `local.properties` 的 `sdk.dir` 或 `ANDROID_HOME`。

```bash
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

APK：`app/build/outputs/apk/debug/app-debug.apk`，当前版本 1.2.0。GitHub Actions 执行构建、测试和 Lint，保存 APK 与报告。调试包用于验证，正式分发请设置自己的 release 签名；不同环境的调试签名可能不一致。

自动测试覆盖提供商与密钥隔离、模型获取、每次请求注入 system 提示词、空提示词回退、双开实例匹配与去重冷却隔离、上下文跨群隔离 / 去重 / 过期 / 长度上限、昵称边界、指纹限流、接口校验和错误脱敏，见 [VALIDATION.md](VALIDATION.md)。

真机仍需验证：小号通知可见 → 正文和回复入口可用 → 绑定正确实例 → API 测试成功 → 大号 @小号 → QQ 实际收到回复。同时检查 @大号、@其他人、关闭开关、移除通知和冷却中不会误触发。未内置真实密钥，未连接用户手机；自动测试不代表完成小米双开或 QQ 真机验证。
